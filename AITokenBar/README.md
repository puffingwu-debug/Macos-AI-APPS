# AI 用量 (AITokenBar)

一个原生 macOS 桌面小窗口，实时显示 **ChatGPT / Codex 的额度使用情况与重置倒计时**，以及 **DeepSeek API 的余额与 token 用量**。

菜单栏也会同步显示剩余百分比，点击可展开完整面板。

三种外观密度，默认「精简」**342 × 153 pt** —— 相当于系统网格两列（360）缩小 5%，
在槽位内左右各留 9 pt 居中：

```
迷你 (198 × 28)     ✦ 57%  3天2h ♛ │ ◈ ¥93.37

精简 (342 × 153)    ┌──────────────────────────────────────────────┐
                    │ ◈ DeepSeek         ┊ ✦ ChatGPT  ♛PRO LITE   │
                    │   ¥93.37           ┊   57%                   │
                    │   余额 CNY          ┊   剩余 · 已用 43.0%     │
                    │   今日 51.45M tokens┊   ▓▓▓▓▓▓▓░░░░░░░░░     │
                    │   预估 ¥5.13        ┊   3天 02:00:10 后重置   │
                    │ ● 剩余 57% · ¥93.37        ⟳ ▣ 详情          │
                    └──────────────────────────────────────────────┘
                    ↑17                   359↑   (槽位 8…368)

完整 (342 × 353)    两列下方再加 7 天趋势与明细行
```

## 快速开始

```bash
cd AITokenBar
./build.sh release run     # 构建 + 启动
```

`dist/AITokenBar.app` 就是成品，可以拖进「应用程序」目录。它是菜单栏应用（`LSUIElement`），不会出现在 Dock 里。

其他用法：

```bash
./build.sh                 # 只构建
./build.sh debug           # 开发用的快速构建

# 不开窗口，直接打印各数据源读到的内容（排查问题很有用）
./dist/AITokenBar.app/Contents/MacOS/AITokenBar --scan-once

# 把三种密度各渲染成 PNG（不需要录屏权限即可检查样式）
./dist/AITokenBar.app/Contents/MacOS/AITokenBar --render preview.png
#   → preview-mini.png / preview-compact.png / preview-full.png

# 吸附几何自检
./dist/AITokenBar.app/Contents/MacOS/AITokenBar --self-test

# 按指定背景色渲染，用于和系统小组件比对本体亮度
./dist/AITokenBar.app/Contents/MacOS/AITokenBar --render out.png --bg 86,96,82
```

> ⚠️ `--render` 用的是 `ImageRenderer`，它**不会把材质与背景合成**——材质在离屏渲染里是平的。预览可以用来检查排版，但**不能用它判断颜色和通透度**，那必须用 `screencapture` 抓真实窗口。这一点在早期版本上踩过坑：预览是深色、实时窗口却是奶灰色。

## 数据从哪来

所有数据都在本机读取，除了下面明确列出的两个 HTTPS 接口外不发任何请求。**不需要登录、不需要填任何必填的密钥**——它会自动复用这台机器上已有的登录状态。

### ChatGPT / Codex

| 项目 | 来源 |
|---|---|
| 已用 / 剩余百分比、窗口长度 | `~/.codex/sessions/**/rollout-*.jsonl` 里每个 `token_count` 事件携带的 `rate_limits` |
| 重置时间 | 同上，`resets_at`（Unix 秒） |
| token 明细 | 同上的 `last_token_usage` |
| 会员等级 | 实时接口的 `plan_type` → `auth.json` 里 id_token 的 `chatgpt_plan_type` 声明（离线可读）→ 日志里的 `plan_type` |
| 已用重置次数 | `~/.codex/.codex-global-state.json` → `codex-rate-limit-reset-history` |
| 实时额度（可选增强） | `GET https://chatgpt.com/backend-api/wham/usage`，凭据取自 `~/.codex/auth.json` |

> 本地日志就是 ChatGPT 桌面端「剩余 57%」那个数字的同一个来源，因此完全离线也能显示。上面那个实时接口是 Codex CLI 自己在用的非公开接口，网络不通时会自动退回本地日志，不会报错刷屏（连续失败 3 次后改为 15 分钟重试一次）。

**关于 primary / secondary**：这两个只是传输槽位，并不固定代表「5 小时」和「每周」。程序一律按 `window_minutes` 判断窗口类型（300 = 5 小时，10080 = 每周，43200 = 每月），所以 Plus / Pro / Team 账号都能正确显示。

### DeepSeek

| 项目 | 来源 |
|---|---|
| 余额、充值余额、赠金余额 | `GET https://api.deepseek.com/user/balance`（官方接口） |
| 今日 / 7 天 / 30 天 token 数、请求数 | 本机 `~/.dsh/sessions/**/session.v3.jsonl.zstd` 会话日志 |
| 累计消费金额、消费金额、API 请求次数、Tokens | 可选的平台会话 Token（见下） |
| 本机记录消费 | 余额差值账本（见下） |

API Key 的解析顺序：设置里手动填的 → 环境变量 `DEEPSEEK_API_KEY` → `~/.dsh/.credentials.yaml`。一般什么都不用做就能用。

**为什么需要「本机记录消费」**：DeepSeek 官方 API 只有 `/user/balance` 一个账户接口，**没有**任何用量统计接口，累计消费和请求次数只存在于网页 dashboard。所以程序用两个办法补上：

1. **余额差值账本** — 每次刷新都记录余额，把余额的「下降」累加为消费（余额上涨视为充值，不计为负消费）。从程序第一次运行开始统计，因此在设置里会明确写成「本机记录」，不会假装知道历史总额。
2. **平台会话 Token（可选）** — 填上之后可以直接读到 dashboard 的真实数字，包括「累计消费金额」。

### 可选：接入 DeepSeek 平台用量

想显示和网页 dashboard 完全一致的数字（累计消费金额 / 消费金额 / API 请求次数 / Tokens）：

1. 浏览器登录 <https://platform.deepseek.com>
2. F12 → Application → Local Storage → `https://platform.deepseek.com`
3. 找到 `userToken`，复制它的 `value`
4. 填进「设置 → DeepSeek 平台会话 Token」

> ⚠️ 这是平台的**非官方私有接口**（`/api/v0/users/get_user_summary`、`/api/v0/usage/by_api_key/*`），随时可能失效。失效时程序只会在设置里提示，其余功能不受影响。API Key（`sk-` 开头）**不能**用于这些接口。

## 功能

- **悬浮小窗**：无边框、可拖动、位置自动记忆，默认贴在屏幕右上角
- **外观密度**：迷你（一行）/ 精简 / 完整，宽度分别 198 / 342 / 342 pt（= 基准值 × `trim`）
- **吸附系统小组件网格**：读取系统桌面小组件（天气、日历…）的真实位置，推出它们的排布网格（本机为左边距 8 pt、行列间距 180 pt），拖到附近就吸附到同一网格线上；同时支持屏幕边缘/角落吸附，靠近时显示对齐预览；改变密度后仍会贴住原来的边
- **窗口层级**：贴在桌面（被窗口遮挡）/ 浮动置顶 / 普通层级，点标题栏的图标循环切换
- **会员等级**：ChatGPT 后面的徽章直接显示套餐（Pro Lite / Plus / Pro / Team…），鼠标悬停可看账号与来源
- **实时刷新**：倒计时每秒跳动；本地日志每 3 秒增量扫描；余额默认每 60 秒刷新（都可在设置里改）
- **精简模式**：只保留关键数字，窗口自动缩短
- **不透明度**：0.35 – 1.0 可调
- **菜单栏**：显示剩余百分比，点击展开完整面板
- **开机自启**：设置里可开启（需要先把 App 放进「应用程序」目录）
- **成本估算**：内置 DeepSeek Flash / V4 Pro 价格，自动区分高峰 / 低谷（高峰 = 周一至周五 09:00–12:00、14:00–18:00，价格为低谷 2 倍），也可自定义单价

## 性能说明

这台机器上 `~/.codex/sessions` 有 **1.7 GB**，所以扫描器是按「永不卡顿」设计的：

- 只考虑保留窗口内（默认 8 天）被修改过的文件
- 首次见到一个文件时只读**末尾 8 MB**，绝不从文件头开始
- 已解析过的文件从上次的**完整行边界**继续（增量、无损）
- 每次刷新有时间预算，超时就下一轮继续，界面始终可用

实测首次扫描 < 100 ms，之后每次约 10–30 ms。历史数据会在后台几轮里逐步补齐，此时卡片状态显示「正在后台补全历史」。

**已知取舍**：首次运行时，如果一个超大会话文件 8 MB 的尾部覆盖不到当天更早的内容，当天 token 数会偏小；从第二次运行起就是精确的增量累加。

## 凭据与隐私

- 所有凭据（DeepSeek API Key、平台 Token）只保存在本机 `UserDefaults`（`~/Library/Preferences/local.aitokenbar.app.plist`）
- 会话日志只在内存中解析，不回传、不上传
- 出网请求仅限：`api.deepseek.com`、`platform.deepseek.com`、`chatgpt.com`（且后两者均可关闭 / 不配置）

## 界面与几何

窗口尺寸随密度变化，内容高度由 SwiftUI 实测后回写窗口。**位置以「上边缘 + 左边缘」保存**——窗口是向下生长的，存左下角原点会让高度变化把窗口顶偏（早期版本正是因此偏了 105 pt）。

吸附分三层：

1. **系统小组件网格**（`DesktopWidgetGrid.detect`）— 从窗口服务器读出 `layer < -1_000_000` 的那些窗口（就是桌面小组件），取它们的列左边缘、行顶边，用最小正间距作为网格步长。只检测当前有小组件的行列是不够的：空行也必须是吸附目标，所以网格会按步长向下/向右投影出完整点阵。
2. **屏幕边缘与角落** — 边距取网格的左边距，顶边与可见区顶部齐平（正好等于系统第一行小组件的位置）。
3. **无网格时**退回纯边缘吸附。

吸附几何是纯函数 `SnapMath`，与窗口生命周期无关，`--self-test` 会验证 14 种情形（贴边 / 角落双轴 / 中央不吸附 / 超阈值 / 已对齐 / 越界回拉 / 网格行 / 空行 / 网格列 / 右边缘对齐 / 无网格回退）。`--grid` 会打印本机实测到的网格。

> 本机实测：系统小组件列在 x=8、188，行顶边在 y=941、761、581，步长 180 —— 即左边距 8 pt、行列各 180 pt。

外观是**照着系统桌面小组件实测校准的**，不是凭感觉调的。方法：`screencapture` 抓 2× 原始分辨率截屏，采样同一 y 上「组件本体」与「紧邻壁纸」的颜色，算遮挡比。

| | 本体亮度 | 相邻壁纸 | 遮挡比 |
|---|---|---|---|
| 系统 · 日历 | 0.22 | 0.27 | ~0.6 |
| 系统 · 电池 | 0.18 | 0.31 | ~0.55 |
| **本组件** | 0.150 | 0.304 | **0.49** |

结论：系统小组件是**接近不透明的深色玻璃**——本体亮度只有壁纸的一半左右，且基色接近纯黑（拟合结果约 `mix(backdrop, rgb(10,10,10), 0.6)`）。

所以表面用 `.regularMaterial`（保留背景模糊）+ 一层**显式黑色 `opacity(0.16)`**。显式叠加而不是依赖材质自身的明暗变体，是因为材质会按 AppKit 外观选变体，而在无边框透明面板里它解析成了**浅色**变体（文字却是深色模式的白色）——结果就是一块奶灰色卡片。显式叠加不会这样漂移。

外框是一条**清晰可见的 1pt 亮发丝线**（深色模式下 `white 0.38 → 0.22` 自上而下渐变）。系统小组件的这条线是实打实的特征，早先版本用的 `primary.opacity(0.08)` 太弱，几乎看不见。

圆角 26 pt（系统小组件在相近宽度下大致是 22–26 pt）；提供方名称 17.5 pt、主数值 29 pt、辅助行 11 pt；两列之间用 1 px 细线分隔，和天气组件里逐小时那一排的分隔线同一套语言；数值一律 `monospacedDigit()`，倒计时跳动时不会左右抖。

## 尺寸微调（trim）

`WidgetDensity.trim` 是全局缩放系数，默认 `0.95` —— 所有度量（宽度、字号、圆角、间距）都乘上它，改一个数就能整体缩放而不必逐个调。

宽度缩到 342 之后，窗口不再正好占满两列网格槽，吸附逻辑会把它**在槽位内居中**（左右各 9pt），而不是留下单边空隙：

```
槽位:  8 ───────────────────────────── 368   (180 × 2)
窗口:      17 ──────────────────── 359        (342 = 360 × 0.95)
            ↑ 9pt                       9pt ↑
```

判定规则只有一条：窗口占据「能装下它的最少整列数」，然后在这个跨度里居中。当宽度正好等于 `列数 × 180` 时，居中位置就等于齐平位置，两种情形自然统一。

网格候选点优先于屏幕边缘候选点——否则窗口已经在 x=8 时，到「齐平」的距离是 0，永远轮不到居中的 17。
